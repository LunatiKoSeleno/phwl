# suposiciones de foros/GitHub, sino en el Query Log real de Pi-hole
# (fichero de 6564 consultas, telefono 192.168.3.11, app ThinQ).
#
# Hallazgo clave: parte del bloqueo NO es por lgthinq.com directamente,
# sino por "CNAME cloaking". La app ThinQ resuelve dominios amigables
# (ej. route.lgthinq.com) mediante un CNAME hacia dominios ofuscados
# tipo *-com.aws-thinq-prd.net / *-com.lgemp-prd.net. Algun blocklist
# (no es HaGeZi, ya lo comprobamos) tiene esos dominios ofuscados en su
# lista negra exacta, y eso arrastra el bloqueo del dominio "bonito" via
# inspeccion profunda de CNAME (status 11 en el log).
# ==========================================

# RECOMENDACION EXTRA (regex, no dominio exacto):
# Para blindarte ante variantes que no han aparecido aun en el log
# (otros servicios de la app que usen el mismo patron de CNAME ofuscado),
# anade estas 3 entradas como REGEX en Pi-hole (Domains > Allow > Regex):
#
#   (\.|^)aws-thinq-prd\.net$
#   (\.|^)lgemp-prd\.net$
#   (\.|^)esi-prd\.net$
#
# Esto permite cualquier subdominio bajo esos 3 dominios raiz, que son
# exclusivos de la infraestructura CNAME de LG ThinQ (no comparten
# hosting con otros servicios que hayamos visto en el log).
